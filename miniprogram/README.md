# 日常小决定 · 微信小程序

AppID：`wx3b755ea7217f2cc0`。原生微信小程序，与仓库 H5 共用菜单规则、90 条日历内容、本地菜单与待办规则。

## 导入与预览

1. 下载这个分支的仓库 ZIP 并解压（或下载 Actions 的 `wechat-miniprogram` 产物）。
2. 微信开发者工具 → 小程序 → 导入，**项目目录选择 `miniprogram/`**，不要选择仓库根目录。
3. AppID 使用 `wx3b755ea7217f2cc0`，基础库选择 3.4.0 或以上。代码已生成，不用安装 npm、构建 npm 或配置云开发。
4. 点击编译查看页面，点击预览扫码在手机上验证。照片随主包包含在项目内。

游客转盘、自定义菜单、日历文字及待办不需要后台服务。日历照片是主包内的本地资源，无需联网下载；无法读取时展示备用画面。

## 当前版本

- 排版沿用 H5 首页：顶部日历摘要，下面是餐食/咖啡切换和转盘；编辑菜单位于转盘卡片右上角，恢复默认放在编辑弹窗内。
- 已移除小程序天气和账号入口；启动时不恢复登录、不请求天气、不进行云端同步，也无需配置这些服务的合法域名。
- 菜单与待办仅保存在当前设备，保留原有本地存储 key；H5 与小程序本地数据不会自动互相迁移。
- 90 条日历轮换、历史日期、经典全文、微信分享日期、生成图片、预览和保存相册继续保留。
- 今天可以新增、完成或删除待办，往日待办只读。
- 原账号和天气适配文件保留作历史实现参考，不在应用启动或注册页面中使用。H5 的天气和账号功能保持原样。

## 后续与 H5 同步

在仓库根目录运行：

```sh
npm install --no-save --package-lock=false sharp@0.34.3
node scripts/build-miniprogram.cjs
```

脚本从 H5 生成 `generated/` 核心逻辑、目录、来源指纹及压缩照片；不要手工编辑生成文件。**H5 新增 UI 或业务流程仍需同步适配原生页面**，构建脚本不会把 DOM 页面自动转成 WXML。

CI 检查生成内容是否与 H5 一致、菜单和账号规则、原生页面行为、请求格式、JS 语法和包体，并使用 `miniprogram-compiler@0.2.3` 包装的 WXML/WXSS 编译器检查模板与样式；通过后上传 `wechat-miniprogram` 产物。编译器检查不代替最新微信开发者工具运行。含 90 张照片的整个主包低于 2 MB。

## 发布前真机验收

1. 编译无报错；转盘在 2/6/10 个选项下指针和结果一致，保存菜单并重启后仍在。
2. 查看今日与历史日历，连续换日期、断网及重新联网；照片不能串日期。跨北京时间午夜检查今日待办。
3. 生成诗句/长故事图片，检查长文字和日期无裁切；预览、允许/拒绝/取消相册保存均有正确反馈。
4. 转发日历给另一微信账号，打开后日期一致。朋友圈分享受微信单页模式限制，应在普通打开方式中继续完整交互。
5. 重启小程序后检查自定义菜单和待办仍在，启动时没有天气或账号请求。

本环境没有微信开发者工具或手机，Node 模拟平台测试不能代替上述验收。代码交付不代表已上传、提交审核或上线。

日历照片压缩为 480 像素并随主包提供，首页及日历直接读取本地资源；无需照片域名或分包加载 API。

## 朋友圈分享

首页和日历页的分享统一从微信右上角“···”菜单选择，不在页面底部重复提供分享按钮。餐食与咖啡使用各自的本地插画封面与标题，分享链接保留当前模式；日历使用当天照片和文字，链接保留所选日期。两张 600×600 封面随代码包提供，不依赖图片域名。

日历默认按一屏布局，长故事在正文区内滚动，日期切换和保存按钮保持可见。点击保存图片直接保存到手机相册，失败时提供预览和权限设置入口。朋友圈分享卡片、打开链接和相册权限仍须在手机微信中实测；工具模拟器不代表正式发布。

短句与中等长度正文按实测高度分配空间，照片填充剩余区域；长故事正文内部滚动。保存时不显示生成预览，只有保存失败才显示恢复弹窗。相册权限未开启时，用户点击“去授权”打开微信设置，授权后自动继续保存；不自动替用户开启权限。
