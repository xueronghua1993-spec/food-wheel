# 踩坑记录

记录可复用的经验，不代替任务进度日志。以下记录于 2026-10-10（北京时间）。

## 1. 云端分支可能落后于线上代码

- 现象：接入 GA4 时，云端代码只有早期日历内容；远程主分支已有 90 天内容、待办和天气功能。
- 原因：云端工作区快照不保证与远程主分支同步。
- 处理：获取 `origin/main`，把本任务的独立提交合入最新代码，解决冲突时保留天气模块。
- 预防：修改及发布前检查 `git status --short` 和分支差异；禁止强制推送覆盖远程。
- 验证：同步后 18 项测试通过，最终对主分支只新增 GA4 代码。

## 2. 新增脚本可能影响发布检查的脚本选择

- 现象：`.github/workflows/pages.yml` 通过第一个不带属性的 `<script>` 标签提取转盘业务脚本。
- 原因：该检查依赖标签顺序与写法；在页面前部新增同类标签会误选统计脚本。
- 处理：GA4 初始化脚本使用 `type="text/javascript"`，保留现有业务脚本选择结果。
- 预防：新增或移动脚本时同时检查 CI 提取逻辑；若未来调整检查，改为明确定位业务脚本。
- 验证：检查全部普通内联脚本语法、GA4 配置队列及 CI 选中的菜单校验函数。

## 3. GitHub CLI 认证失败不等于 Git 推送失败

- 现象：`gh auth status` 报告凭据无效，但 Git 读取和推送仍然成功。
- 原因：两种工具可能使用不同认证通道，单个检查无法说明全部能力。
- 处理：分别验证 Git 读取、推送与工作流查询。此次通过 Git 推送，并通过 GitHub 工作流页面确认发布成功。
- 预防：保持平台提供的代理和凭据配置，不泄露令牌、不绕过网络限制；只针对实际失败能力报告阻塞。

## 4. 统计代码上线与收到真实访问是不同的验证

- 现象：本地初始化检查和 Pages 部署成功，不能证明 GA4 后台已经收到访问。
- 原因：真实数据还受浏览器网络、拦截器和统计处理时间影响。
- 处理：分别报告代码验证、发布状态及尚待后台确认的数据接收状态。
- 预防：在 GA4 实时报告确认访问，省份分布通过地区（Region）维度查看；IP 推断的地区不等于用户常住地。
- 验证边界：此次已确认 GA4 初始化和 Pages 发布成功，未直接访问用户 GA4 后台验证数据接收。

## 5. 登录与同步必须区分游客、本地账号缓存和云端数据

- 游客数据使用原有 key；账号数据使用 user_id 命名空间。退出时恢复游客数据，不能把账号内容当作游客数据。
- 待上传操作和账号缓存用一个快照保存；只确认已经上传的操作，避免旧请求吞掉新修改。
- Supabase 登录状态回调中不 await SDK 方法；把后续同步放到回调外执行，避免 SDK 内部锁等待。
- 首次导入须由用户选择，保留已有云端菜单；待办导入生成 UUID，并记录导入映射以避免重复。
- 验证分层：浏览器模拟两设备同步、SDK 模拟 HTTP、真实项目只读权限检查、用户实测邮件和真实 RLS。不能把前两项当作真实账号验收。

## 6. 注册成功提示需要独立状态，并尊重邮箱确认设置

- 注册请求成功且没有 session 时，收起表单并显示邮箱确认步骤；返回登录保留邮箱、清空密码。
- 如果 Supabase 返回 session，表示无需邮件确认，进入账号流程，不能误报已发确认邮件。
- 密码字段应注明本站登录密码，注册时说明不是邮箱密码；身份请求期间禁用切换，避免响应落到错误页面。
- 验证界面切换不代表真实邮件送达；邮件确认须在生产由用户实测。

## 7. 小程序导入必须先读云端，且菜单插入不能覆盖并发创建

- 首次鉴权成功不代表云端数据读取成功；小程序导入先成功同步并核对账号 epoch，读取失败保留导入待确认状态。
- 原生账号队列把游客菜单导入标记为 `importOnly`，与队列原子保存；发送时用 `resolution=ignore-duplicates`，避免检查到上传之间覆盖另一设备刚创建的菜单。普通菜单编辑仍使用覆盖更新。
- 天气页面成功和失败分支都检查请求序号，防止旧城市请求失败覆盖新城市成功结果。
- 已通过离线首次导入、并发菜单创建和过期天气失败的 Node 回归测试；真实服务及微信域名仍需实机验证。

## 8. WXML 检查不能只依赖 XML 解析

- WXML 允许布尔属性、`wx:else` 和插值表达式中的 `&&`，XML 检查需做对应归一化。
- 在 WXML 插值中写 `&lt;` 不会变成比较运算符，wcc 会报 unexpected semicolon；使用等价的 `>=`、`===` 表达式。
- 运行 `node scripts/check-miniprogram.cjs` 使用 WXML/WXSS 编译器检查；WXSS 包装器可能返回 Error 而不抛出，必须显式判断。编译成功不代替微信开发者工具及真机运行。

## 9. 日历照片必须在小程序实际可访问的包内

- 小程序运行时没有 `wx.loadSubpackage`；不要将小游戏加载接口当作小程序接口，测试也不能凭空模拟该 API 来证明运行可用。
- 90 张照片压缩至 480 像素、JPEG quality 50 后，含代码整个主包约 1 MB；照片随主包提供并直接按本地路径读取。
- 验证：无分包 API 的页面测试、主包小于 2 MB 检查，以及开发者工具中首页、完整日历和换日期的实际照片显示。
