# 把 DeepSeek 餐食推荐接进“日常小决定”

这份说明按你已有 DeepSeek 开放平台账号、每月预算希望在 20 元以内来写。

代码已做好：用户选预算、口味、忌口，得到 3 个建议，再点“放进转盘”。第一版需要试用码。没有配置后端地址时，网页不会显示 AI 入口。

你需要亲自完成的是开通阿里云、在自己的控制台配置密钥与资源。我没有你的云账号权限，也没有替你充值或开通收费资源。代码测试使用模拟回复，真实 DeepSeek 和 OSS 连接需要在配置后验证。

## 第 1 步：先理解钱花在哪里

DeepSeek 负责回答；阿里云函数计算负责转发和检查；阿里云 OSS 只保存调用次数。三项可能分别收费，免费额度以你账户实际显示为准。

默认全站最多每天 20 次、每月 300 次。同一访问来源每分钟 1 次、每小时 3 次，每次模型最多输出 600 Token，不自动重试模型。失败也占一次额度，避免重复请求偷偷增加费用。每次输入只有固定预算、口味和最多 5 项忌口。

这些上限控制调用量，不是人民币硬封顶。云函数、OSS 请求、日志及流量也可能收费；恶意请求即使没有调用模型，也可能产生云平台费用。开始前查看账单规则：若存在固定月费、预留实例或必须购买的资源包，先不购买；若服务显示预计费用超出 20 元，就先停在本地测试。

建议 DeepSeek 先少量充值且关闭自动充值（若账户提供该功能）；阿里云设置 10 元和 15 元费用提醒，每周检查账单。告警只提醒，不会自动停机。接近预算时按文末方法停用，不能保证滞后入账的费用恰好在 20 元停止。

官方说明：[DeepSeek API](https://api-docs.deepseek.com/zh-cn/)、[函数计算 Web 函数](https://help.aliyun.com/zh/functioncompute/web-function-quick-start)、[OSS 计费](https://help.aliyun.com/zh/oss/product-overview/billing-overview)。

## 第 2 步：开通阿里云，建一个私有“小账本”

1. 注册阿里云账号，完成平台要求的实名认证。
2. 在对象存储 OSS 中建一个 Bucket（可以理解成文件夹仓库），地域选中国内地杭州，存储类型选标准存储。
3. 访问权限选“私有”，开启阻止公共访问；不要开放匿名读写，不需要配置跨域。关闭版本控制，不开传输加速，不创建固定套餐。
4. 记下 Bucket 名称，后面填到 `OSS_BUCKET`。
5. 对 `meal-quota/` 前缀设置“创建 40 天后删除”的生命周期规则。不要设成 7 天，也不要手动删除本月文件，否则本月计数会清零。按月份统计的文件只有匿名来源哈希和时间，不保存口味、忌口、密钥或试用码。

这里使用 OSS 而不是购买数据库，是为了减少固定费用。程序写计数时会检查文件末尾的位置，两个人同时请求时只能有一个先写成功，另一个会重新检查额度。读取或写入失败时停止推荐，不绕过记账。

## 第 3 步：给云函数开一张只读写计数的“工作证”

在 RAM 访问控制中创建受信服务为函数计算的角色，按函数计算控制台的引导关联到函数。角色只需读写上面的计数前缀，不需要全账户管理员权限。

创建权限策略时，把下面的 `你的Bucket名称` 替换为第 2 步创建的实际名称，策略关联到该函数角色：

```json
{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["oss:GetObject", "oss:PutObject"],
    "Resource": ["acs:oss:*:*:你的Bucket名称/meal-quota/*"]
  }]
}
```

函数计算通过角色提供临时凭据。不要创建长期阿里云 AccessKey 发给我，也不要把它写进仓库。后端需要运行时提供 `ALIBABA_CLOUD_ACCESS_KEY_ID`、`ALIBABA_CLOUD_ACCESS_KEY_SECRET`、`ALIBABA_CLOUD_SECURITY_TOKEN` 三个临时凭据变量；角色没有生效时程序会停止服务。

不同运行时的角色凭据传递方式可能不同。这里按官方自定义运行时 Debian11 的环境变量方式实现；部署后需要验证，不能只凭“已选角色”就认定能读写。

参考：[函数角色临时凭据](https://help.aliyun.com/zh/functioncompute/context-and-log-format-1)。

## 第 4 步：上传后端代码包

在函数计算 FC 创建 Web 函数，地域也选中国内地杭州，自定义运行时采用支持 Node.js 20 的 Debian11 运行环境。

设置按量运行，预留实例数 0、最大实例数 1、实例并发 1、内存 128 MB、超时时间 60 秒，监听端口 9000。若控制台显示内存最低值更高，按平台最低值，并重新核对费用。打开所需的公网出站能力以访问 DeepSeek；不需要给函数分配固定公网 IP 或购买 NAT 网关。

上传 `artifacts/meal-backend.zip`，设置启动命令：

```text
/var/fc/lang/nodejs20/bin/node /code/backend/meal/server.mjs
```

代码包也包含 `bootstrap` 启动脚本，可按平台支持的默认启动方式运行。

创建 HTTPS HTTP 触发器，允许 POST 和 OPTIONS（OPTIONS 是网页跨域请求前的检查），函数内使用试用码验证请求。不要把 RAM 密钥放进网页用于签名。先把触发器地址保留给自己，不公开推广。

注意：函数公网地址、自定义域名的使用规则及备案要求，以你选用的地域和当前控制台要求为准。默认域名可能带附件响应头；fetch 获取 JSON 的实际行为必须用网页联调验证。若默认地址不可用，需要按平台要求配置自己的域名，可能有域名费用和备案流程。

参考：[自定义运行时](https://help.aliyun.com/zh/functioncompute/custom-runtime/)、[Web 函数调用机制](https://help.aliyun.com/zh/functioncompute/web-functions)。

## 第 5 步：只在后端填密钥

在函数的环境变量或平台支持的密钥配置中填写：

| 名称 | 填什么 |
| --- | --- |
| `AI_ENABLED` | 先填 `false`；其余配置好再改为 `true` |
| `DEEPSEEK_API_KEY` | 你在 DeepSeek 开放平台生成的 API 密钥 |
| `DEEPSEEK_MODEL` | `deepseek-flash`；若账号模型列表不同，按官方当前可用模型修改 |
| `AI_BETA_CODE` | 建议生成至少 24 位随机英文字母数字试用码（程序最低接受 16 位），不使用简单口令 |
| `AI_HASH_SALT` | 建议另一个至少 24 位随机串（程序最低接受 16 位），和试用码不同 |
| `ALLOWED_ORIGIN` | `https://xueronghua1993-spec.github.io`，不带 `/food-wheel/` 或末尾斜杠 |
| `OSS_BUCKET` | 第 2 步创建的 Bucket 名称 |
| `OSS_REGION` | `oss-cn-hangzhou` |
| `DAILY_LIMIT` | `20`（也可以调小） |
| `MONTHLY_LIMIT` | `300`（也可以调小） |
| `HOURLY_LIMIT` | `3`（也可以调小） |

后三项只能调小，错误配置会停止服务。模型调用关闭思考模式。密钥、试用码、盐不要填进网页代码或 GitHub；`ALLOWED_ORIGIN` 只限制正常浏览器来源，不能防住伪造请求，真正的保护是试用码和全站持久配额。

无需把密钥发到聊天中。如果你想让我帮助真实联调，可以使用工作环境提供的安全密钥配置，并配置需要的网络访问；目前环境未配置这些条件。

## 第 6 步：接上网页

在 `ai/config.mjs` 的 `endpoint` 中填公开后端地址，路径要以 `/api/meal` 结束，例如：

```js
export const mealConfig=Object.freeze({endpoint:'https://你的函数域名/api/meal'});
```

这是服务地址，不是密钥，可以公开。不要在这个文件添加任何其他秘密。

重新构建并发布网页后，餐食转盘下方会显示 AI 推荐入口。输入试用码、选条件、生成建议。这里只保留原页面风格，没有把网页变成聊天应用。

网页的条件会发送给 DeepSeek，不保存在浏览器里；试用码只存在当前弹窗内，关闭会清除。弹窗输入和结果做了 Clarity 遮罩，后端不主动记录请求内容。平台访问日志仍可能记录来源或请求元数据；不要开启记录完整请求体、Authorization 或业务变量的调试日志。

## 第 7 步：先做一轮小范围验证

- 正确试用码能生成 3 项，模型费用确实出现在 DeepSeek 账户里；OSS 中出现本月计数文件。
- 错误试用码无法调用模型；快速重复请求被限制，伪造 IP 头不能绕过限制。
- 重启函数后计数仍存在；把 `DAILY_LIMIT` 临时设为 `1`，达到次数后停止，再恢复为 `20`。所有部署版本都必须使用同一个私有桶和前缀。
- 自定义菜单只在确认后被替换；关闭弹窗再打开不会保留试用码。
- 断网、DeepSeek 余额不足或 OSS 权限错误时，原转盘仍可使用。
- 用国内手机网络和微信浏览器验证 HTTPS、跨域、返回 JSON 和加载速度。云代理可能让多人看起来来自同一个连接地址，从而共享每小时额度；第一版宁可保守限制，也不相信可伪造的转发头。若影响试用，再配置可信代理来源识别。
- 看一周真实账单，再决定是否开放更多用户。GitHub Pages 的国内加载稳定性不会因为换了国内后端自动改善。

AI 能漏掉别名、隐藏食材和交叉污染。忌口检查只是一层过滤，不能保证过敏安全；页面已提醒食用前确认食材，严重过敏不要依赖此功能。

## 随时停止的方法

1. 把云函数 `AI_ENABLED` 改为 `false` 并更新生效：停止新的模型调用。
2. 禁用或删除 HTTP 触发器：减少外部请求造成的后端费用。
3. 如有异常，撤销 DeepSeek API 密钥并更换试用码。
4. 网页 `endpoint` 清空并发布：隐藏入口。

停用开关不会追溯撤销已在执行的请求，也不会抹掉已经产生或延迟入账的费用。不要靠删除 OSS 计数文件来停用。
