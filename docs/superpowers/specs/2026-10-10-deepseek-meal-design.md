# DeepSeek 餐食推荐设计

目标：国内用户按预算、口味、忌口获得 3 个餐食建议，确认后替换餐食转盘。既有日历、待办、天气、咖啡和手动编辑保留。

采用 GitHub Pages 前端、阿里云函数计算自定义运行时 Web 函数（Node.js 20，9000 端口）、DeepSeek 官方 Chat Completions API。第一版为邀请码试用，默认关闭，需要部署后端和设置公开 API 地址后才显示入口。没有真实凭据时完成代码、部署 ZIP、模拟浏览器测试和说明，不声称真实调用或部署完成。

请求 POST /api/meal：固定预算档、口味档、最多 5 项忌口（每项 12 字），试用码通过 Authorization 发送，不持久化、不传给模型。只发送餐食条件，无自由聊天或图片。模型输出 JSON {options:[{name,reason,ingredients}]}，严格验证 3 项、菜名最长 8 字、理由最长 60 字、主要食材列表及忌口匹配；名单检查不能覆盖所有别名、隐藏食材或交叉污染，因此页面标明不适用于严重过敏保障，食用前确认食材。

密钥、邀请码、IP 哈希盐仅后端配置。CORS 精确允许网页 origin，但不把它当作身份认证。限制输入 4096 字节、模型输出 600 token、20 秒模型超时、响应体 32 KiB，不自动重试模型。响应用纯文本渲染。禁用后端异常细节输出、禁止日志记录条件/试用码/密钥。表单和结果设置 Clarity mask，不保存用户输入。

费用限制：私有 OSS 标准桶，关闭版本控制，按北京时间月份记录匿名计数日志。AppendObject position 原子竞争，记录成功后才调用模型；每次记录只包含时间和加盐来源哈希，每日最多 20 次、每月最多 300 次、来源每小时 3 次、每分钟 1 次。并发失败重读重判，存储不可用或日志异常则停止调用；模型失败仍计一次。保留 40 天后删除（桶生命周期配置）。来源默认使用连接地址，不信任客户端 X-Forwarded-For；云代理可能导致多人共享来源，保守限制优于信任可伪造地址。全站硬上限才是主要保护，不能保证恶意流量的云函数/OSS费用为零。

后端使用函数角色的临时凭据读写 OSS 的 meal-quota/* 前缀，仅授权 GetObject、PutObject。不把长期阿里云密钥放进代码。只用按量实例，预留实例 0，最大实例数 1，实例并发 1；云平台预算告警配合应用配额，告警不是自动停机。

交付：前端模块与独立弹窗、后端模块、测试、可上传 ZIP、中文逐步操作指南；不会替用户开户、充值或创建收费云资源。用户已有 DeepSeek 开放平台账号，月预算 20 元以内；20 次/日和 300 次/月是试用上限，不是人民币账单保证。上线需实际审核平台费用与当前 API 单价。
