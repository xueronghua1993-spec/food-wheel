# 账户与同步使用说明

## 已确认的范围
- 游客可以直接转盘、编辑菜单和记录待办，仍使用原来的浏览器本地数据。
- 可选邮箱注册、登录、退出、忘记密码；密码由 Supabase Auth 处理。
- 登录后同步餐食/咖啡菜单和按日期保存的待办。打开页面、返回页面、联网或点击「刷新同步」时更新。
- 首次登录询问是否导入本浏览器游客数据；已有云端菜单保留，待办追加；游客数据保留。
- 每个账号的缓存和待上传队列分别保存；退出后回到游客数据。
- 离线失败的修改留在此浏览器，不显示「已同步」。同一菜单同时在两个设备修改时，以最后上传的版本为准；待办按条更新。
- 不支持后台实时推送；另一台设备需重新打开页面或刷新同步。

## 配置在哪里
- `calendar/supabase-client.mjs`：项目地址、publishable 公钥；公开前端配置，不使用管理员密钥。
- Supabase：Authentication → URL Configuration，正式站点与回跳网址。
- Supabase：Email provider、邮箱验证和自定义 SMTP。
- 数据库：`user_menus`、`user_todos`；必须启用 RLS，并按 auth.uid() 限制读写。游客不授予表权限。
- 当前两张表由项目所有者在 Supabase SQL Editor 手动建立。仓库测试不代替对实际 RLS 策略的检查。
- SDK 在 GitHub Actions 打包为本站资源，正式发布不依赖外部 SDK CDN。源码预览使用 esm.sh。

## 如何验收
1. 游客修改菜单、添加待办，刷新后检查仍在。
2. 点击右上角人物图标，注册自己的邮箱；检查邮件（包括垃圾箱）并点击确认链接。
3. 回到测试页面登录，先选择暂不导入；检查没有把游客内容自动放进账号。
4. 导入功能可以换一个未做选择的账号测试：确认云端已有菜单不会被覆盖。
5. 在登录状态编辑菜单、添加和完成待办，等提示「已同步到账号」。
6. 手机浏览器登录同一个账号，点击刷新同步；检查菜单及待办一致。
7. 退出后检查恢复原游客数据；换另一账号，检查看不到前一账号内容。
8. 临时断网修改，检查「尚未同步」；联网重试，检查手机数据更新。
9. 忘记密码：收到邮件后回到页面，填写两次新密码，退出并用新密码登录。

注册和重置邮件回跳固定为正式 GitHub Pages 地址。PR 未合并时，正式页面还没有这套账户界面：注册邮件可以完成邮箱验证，然后回到预览页手动登录；密码重置的完整回跳流程要等正式发布后再测。不要把预览的模拟验证当成真实邮件验收。

## 验证的边界
- 单元测试验证账号/游客隔离、逐条待办变更、失败重试和导入。
- 浏览器测试使用模拟后端检验两个浏览器的数据同步、注册/重置界面及官方 SDK 请求格式，不发送真实邮件。
- 只读线上检查检验邮箱开关和游客读权限；不更改真实数据库。
- 真实邮件送达、真实账号写权限、不同真实账号的 RLS 隔离和真机跨设备同步仍需按上述清单验收。

## 后续维护
仍从最新 main 建分支，通过 GitHub 修改和 Actions 检查；先看 PR，再决定是否合并。不要把 SMTP 授权码或 service_role/secret 密钥放到网页、仓库或聊天里。
